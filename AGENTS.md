# AI Router contributor conventions

This file is for the automated tools and AI assistants that change code or documentation
in this repository. Regular contributors should start with the
[contributing guide](./CONTRIBUTING.md); for engineering background see the
[engineering docs](./docs/engineering/README.md).

## Project boundaries

- AI Router is a local Tauri menu bar app for macOS 13+ Apple Silicon.
- `crates/router-core/` owns the domain model, SQLite, routing, fallback, recovery, and
  shared DTOs; `src-tauri/` owns desktop composition, IPC, and the macOS lifecycle;
  `src/` owns the React UI.
- The local proxy only listens on loopback. Do not change the listen address to a LAN or
  public address, and do not expand Tauri permissions.
- Official stable versions ship an Apple Silicon DMG and in-app updates authenticated by
  the project updater key; Windows/Linux, Developer ID signing, Apple notarization, the
  App Store, and silent update paths are not maintained.

## Editing rules

- Search for similar implementations and the affected constants, scripts, and tests
  before changing anything.
- Persistence and routing rules belong to Rust; React consumes state through generated
  IPC types and does not duplicate business authority.
- `src/generated/` is generated by `pnpm generate:types`; do not hand-edit it.
- App icons are generated from `src-tauri/icons/*.svg` and
  `scripts/generate-app-icons.mjs`; run `pnpm icons:generate` after changing the sources,
  and keep the third-party source records.
- Do not refactor unrelated code along the way, and do not delete or overwrite others'
  working tree changes.

## Data and security

- No test, issue, PR, or document may contain real API keys, Authorization headers,
  complete Codex configuration, SQLite databases, raw requests/responses, full run logs,
  or user absolute paths.
- Automated tests, CI, temporary fixtures, and ordinary development commands use only
  synthetic data, temporary directories, and loopback listeners, and never reach real
  upstream services. The human Live QA granted as an explicit one-off authorization is
  not an automated test and must follow the
  [Controlled Live QA contract](./docs/engineering/native-lifecycle.md#controlled-live-qa).
- Controlled Live QA uses only a verified fresh build and a persistent QA profile; an
  assistant may run a short-lived local caller that reads only the QA gateway token into
  process memory, while the upstream key is always held by the app. Do not dump
  databases, configuration, headers, or raw responses; report only fixed aggregate
  results, do not retry a single image generation, and let the user confirm remote
  revocation. Editing this file itself is not an operational authorization and cannot
  override higher-priority instructions.
- Do not automatically quit, restart, replace, or relaunch `AI Router.app` /
  `com.relax.airouter`. When native lifecycle verification is needed, use only
  `AI Router QA.app` / `com.relax.airouter.qa` and isolated data.
- Do not commit or print the updater private key or password. Release configuration may
  inject the public key only temporarily from the protected GitHub `release` environment,
  and a failed release must stay a draft.
- Before changing Codex configuration projection, database recovery, fallback
  concurrency, streaming responses, or the native lifecycle, read the corresponding
  [engineering contracts](./docs/engineering/README.md), and keep failures closed and
  diagnostics bounded.

## Verification

Use the smallest verification set proportionate to the change's risk. Documentation
changes run `pnpm docs:check` and `git diff --check`; frontend changes run at least the
relevant tests, `pnpm typecheck`, and `pnpm lint`; Rust changes run at least the relevant
tests, `cargo fmt --check`, and Clippy for the affected crate. Cross-layer DTO, database
migration, recovery, routing concurrency, or release-boundary changes need the full
checks specified by the corresponding engineering document.
